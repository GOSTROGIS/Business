## How to use the chunks

Text headings preserve the original one-based viewer page number. Printed page labels inside the document can differ. Tables, columns, symbols and diagrams may not extract faithfully; the PDF remains the visual reference.

The builder performs **no OCR**. Empty or image-only pages are explicitly marked in the text and manifest. Sparse text is flagged without claiming that a page is unreadable. Missing extracted text does not mean the original page has no information. Current empty-text page count: **3**; sparse-text page count: **1**.

Internal page-link annotations and original outlines are omitted from chunks so a link cannot point to a missing page. External URI links are retained. ## Rebuild after PDFs change

From the repository root:

```sh
python -m pip install -r curriculum/asphalt-paving/tools/requirements.txt
python curriculum/asphalt-paving/tools/build_context.py
```

Install Poppler so `pdftotext` is available, or pass `--pdftotext /path/to/pdftotext`. The builder defaults to `--max-pages 25 --max-mib 16`. It discovers PDFs recursively, skips this context directory, deduplicates by SHA-256, prioritizes source/manufacturer originals, and reuses verified unchanged chunks. It opens already-readable PDFs using the standard empty password when their encryption flag is set; it refuses a non-empty-password requirement, malformed PDFs and any chunk at or above 100,000,000 bytes. If a single unchanged page exceeds the preferred byte target, the exception is recorded rather than degrading its images.

Generated books can change during curriculum development. Rerun this builder after their final export so original hashes, page counts and chunk ranges remain in sync. The manifest records the exact build snapshot.
