# Parcel lookup in Site Planner

The Parcels tab provides explicit lookups for **NWT surveyed parcels** and **Canada Lands parcels**. The active choices come from `ACTIVE_PARCEL_PROVIDER_IDS` in the parcel adapter. United States parcel expansion is deferred under the Canada-first checklist; existing published U.S. civic search and travel tools remain unchanged.

Select a source and enter its exact identifiers, or choose a map point and then select **Find parcels**. Choosing a point alone sends no request. The adapter rejects incomplete/overflow results instead of exposing a partial set. Every accepted result is available across ten-row pages, with the complete original record and source metadata under **Source and original fields**.

**Use parcel as site** selects the returned parcel record, clears old route comparisons, and displays its boundary as **Site parcel** in Contents. It creates no routing point. Place and confirm a physical entrance separately to calculate a road route. The provider's country controls the manual-entry country selector; it is not added to the original source attributes.

Selected records preserve all returned attributes, unknown fields, nulls, blanks, signed zero, legal components, top-level response metadata and returned Esri geometry, including Z/M ordinates. The adapter requests WGS84 coordinates from the service. This is preservation of the returned geometry, not a claim of byte-identical native cadastral coordinates. The display converter creates separate XY GeoJSON rings, keeps every XY vertex and groups holes, islands and disconnected parts by containment. It may reverse a display ring for GeoJSON winding; the original returned rings remain untouched.

Unsupported CRS, antimeridian wrapping, curves, crossing/touching or degenerate rings, and excessive topology work produce a display error. The source record remains selected and available; an old boundary is removed rather than shown as the new result. A null-geometry record is selectable without a fabricated polygon or centroid. The converter permits at most 40,000 vertices, 2,048 rings and 1,000,000 topology checks and never simplifies a boundary to fit these limits.

Contents supports styling, zoom and removal through the existing overlay integration. **Show parcel** restores a selected boundary after removal. Clear map removes the boundary, pins and routes, cancels pending lookups/pick modes and ignores late responses. Reload restores the selected record only: no automatic overlays or external requests. Only the explicitly selected site is stored locally through the existing 256-KiB address model; result lists and route responses are not persisted.

## Integration

`mountSitePlanner` retains its existing API and accepts optional `parcelLookup` dependency injection for deterministic tests. It imports `parcel-panel.js`, `parcel-providers.js` and `parcel-geometry.js`; the existing `site-planner.css` carries the additional tab/form rules. No new root atlas hooks or external stylesheet links are required.

`entries()` adds `{title:'Site parcel',layer,revision,remove}`. The layer contains feature-bearing Leaflet polygon children. Its revision changes when the boundary changes, allowing the existing Contents symbology domain refresh. Own Site Planner layers remain excluded from loaded destination inventory. A parcel boundary is not a supplier destination or physical entrance.
